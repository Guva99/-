# Частицы — фигуры по скроллу

Страница без контента: только фоновое поле из контурных треугольников,
которое пересобирается в узнаваемые фигуры при прокрутке.

Статика без сборки и зависимостей: откройте `index.html` или поднимите любой статический сервер.

```bash
python3 -m http.server 8000
# http://127.0.0.1:8000
```

## Структура

```
index.html         канвас и шесть пустых экранов с data-formation
assets/styles.css  белый холст, fixed-канвас, размеры слотов
assets/main.js     система частиц и формации
```

## Как это работает

Один `position: fixed` канвас на весь экран, 5200 контурных треугольников
(2000 на мобильных). Размеры от 1.5px до 70px по кривой `pow(r, 5.6)` — мелкая
«пыль» с редкими крупными бледными фигурами. Палитра: серые `#E8E8E8` / `#BFBFBF`
/ `#7B7B7B` и оранжевые `#FD622C` / `#FC5922` / `#C24A22` / `#FFDBCE`.

Позиция каждой частицы — чистая функция прокрутки: поле **перетекает** из
фигуры в фигуру, а не пересобирается заново. Страница делится на экраны с
атрибутом `data-formation`; на каждом кадре берутся две соседние фигуры и доля
пути между ними, и частица линейно интерполируется между своими целями в них.
Пока экран близко к центру, фигура держится; перетек занимает среднюю треть пути
(`ease()` со smoothstep).

| Экран | Фигура |
|-------|--------|
| 1 | хаос: сгустки со смещением плотности вправо |
| 2 | лампочка с надписью UP внутри |
| 3 | планета: шар с материками, Европа–Россия–Индия |
| 4 | плотные абстрактные волны по низу экрана |
| 5 | проблемы: два серых пазла врозь — сверху слева и справа |
| 6 | решение: серый и оранжевый пазлы состыкованы, через них линия связи |
| 7 | облако реплики с кавычками |
| 8 | конверт |

Цели каждой фигуры считаются один раз и сортируются по углу вокруг центроида,
поэтому частица занимает одно и то же угловое место во всех фигурах — переход
читается как согласованное течение, а не как случайное перемешивание.

**Планета** собрана из настоящей карты. Контуры материков заданы полигонами в
градусах долготы и широты (`LANDS`), растеризуются в равнопромежуточную маску
720×360, после чего точки сферы проверяются по ней. Поворот зафиксирован: к
зрителю повёрнута долгота 45° в.д., взгляд приподнят к северному полюсу — в
кадре Европа, Россия, Индия и Африка. Проекция ортографическая, без
перспективы: иначе точки средних широт выпирают за кольцо лимба и силуэт
перестаёт быть окружностью. Частицы садятся только на видимую сторону, ещё 8% держат лимб —
без чёткого края шар на белом не читается.

Шар доворачивается вместе со скроллом: угол поворота берётся из положения
секции относительно центра экрана, точки, ушедшие за край, гаснут.

Размер треугольников одинаков во всех сценах — 1.2…4.6px, — иначе фигуры
заметно меняли калибр на переходах. Задаётся полем `size` при создании частиц
в `assets/main.js`; `data-scale` в разметке отвечает за размер **фигуры**,
а не частиц.

**Волны** занимают низ экрана целиком, без слота. Верхняя кромка — сумма
четырёх гармоник, поэтому узор не повторяется по ширине; под ней плотное тело,
внутри — дополнительные гребни, сверху — редкая взвесь.

Куски пазла собираются из квадрата со скруглением: выступы прибавляются
кругами, впадины вычитаются через `destination-out`. Каждый кусок рисуется в
отдельном буфере — иначе вырез одного стирает выступ соседнего. Ширина и
высота задаются раздельно, потому что сцена растянута во весь экран и квадрат
в буфере стал бы на экране прямоугольником.

Цвет задаётся атрибутом `data-tint`: `grey` красит всю сцену в серые токены,
`split` делит по вертикали — левый кусок серый, правый оранжевый, и они
стыкуются.

Переход «волны → проблемы» помечен `data-enter="tornado"`: частицы разлетаются
по спирали, сжимаясь в мелкую пыль, и оседают в форму пазлов.

Переход «планета → волны» помечен `data-enter="fall"`: у каждой частицы своя
задержка, по вертикали движение идёт с ускорением, а в середине пути добавляется
разлёт в стороны — шар распыляется и осыпается вниз.

Мозг задан процедурно, но сейчас на странице не показан — чтобы вернуть его,
достаточно поставить `data-formation="brain"` на любой экран.

Остальные фигуры рисуются обычными командами канваса
в офскрин-буфер 220×220, после чего непрозрачные пиксели становятся целями для
частиц — см. `rasterise()` в `assets/main.js`. Чтобы добавить свою фигуру,
достаточно дописать функцию рисования в объект `SHAPES` и повесить
`data-formation` на новый экран.

Каждый экран содержит пустой квадрат `.figure-slot`; поле каждый кадр берёт из
него центр и масштаб, поэтому фигура собирается ровно в нём и подстраивается
под размер устройства.

Положение и наклон задаются в разметке:

- классы `stage-left` / `stage-right` — фигура уходит в левую или правую
  половину страницы (на экранах уже 720px остаётся по центру, иначе была бы
  слишком мелкой);
- `data-rotate` — поворот в градусах вокруг центроида фигуры, отрицательное
  значение вращает против часовой стрелки;
- `data-scale` — множитель размера фигуры, ограничен высотой экрана, поэтому
  фигура не обрезается на невысоких окнах;
- `data-size="mixed"` — калибр частиц на сцене разбавлен крупными
  треугольниками (стоит на первом экране);
- `data-enter="fall"` — вход в сцену через осыпание.

У лампочки: `stage-right`, `data-rotate="-30"`, `data-scale="2"`.

## Производительность

Кадр собирается в бакеты «цвет × квантованная альфа × толщина линии» — не больше
84 вызовов `stroke()` вместо 2800. Фигуры за пределами вьюпорта отсекаются,
рендер останавливается, когда вкладка скрыта.

`prefers-reduced-motion` выключает анимацию: поле рисуется одним статичным кадром.
